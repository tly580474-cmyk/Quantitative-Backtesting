# TDX TCP 在线分钟源落地计划

> 当前状态（2026-08-31）：TDX TCP 已设为生产主源，固定降级顺序为 TDX TCP → 新浪 → 本地 `.lc1`。以下“候选主源”“正式切换前”等内容保留为实施过程记录；不会因单次故障自动切回新浪主源。

## 1. 背景与目标

当前分钟湖的新浪 HTTPS 全市场更新存在 HTTP 456、TLS EOF、连接重置和耗时波动，导致近期频繁依赖人工通达信 `.lc1` 回补。本计划引入基于通达信公开 TCP 行情协议的 `tdx-tcp` Provider，作为与新浪/东财 HTTPS 链路独立的在线分钟源。

目标：

- 支持沪、深、北交所 1 分钟 OHLC、成交量和成交额；
- 在不放宽现有覆盖率、时间轴和最终日线对账门禁的前提下，将全市场更新稳定在 10 分钟内；
- 任一服务器或 Provider 失效时可自动降级；
- 任务中断后可复用已成功抓取结果；
- 正式切换前先完成连续 3 个交易日的影子运行。

## 2. 已验证的可行性

2026-08-27 对 `lierwang19/pytdx3` 和本机已安装的 `pytdx 1.72` 进行了隔离实测：

- `pytdx3` 单元测试 54/54 通过；
- 47 个候选地址中 7 个能完成真实行情协议调用；
- 100 股随机样本包含深市45、沪市48、北交所7，目标日 100/100 均返回 240 根；
- 100 股串行耗时 5.69 秒，推算全市场单连接串行约 5.26 分钟；
- 实测可读取约 22,320 根历史 1 分钟 K 线，覆盖 2026-04-15 至当日；
- 沪深北样本与 2026-08-26 本地 TDX Parquet 的240根时间轴一致，收盘、量额基本一致；
- `pytdx3` 与已安装 `pytdx 1.72` 的同服务器返回数据哈希一致。

因此首期复用已安装的 `pytdx 1.72`，不新增 `pytdx3` 运行时依赖；参考其服务器池、心跳和重连设计。

## 3. 目标架构

```text
盘后分钟更新
  → TDX TCP 在线源（正式主源）
  → 新浪在线源（自动降级）
  → 本地通达信 .lc1（最终回补）
  → Tushare（有分钟权限时可选）
```

影子任务仍可独立抓取与对账；正式更新任务已由 TDX TCP 写入 Parquet 和 `manifest.json`，失败时按既定顺序降级。

## 4. 实施阶段

### 阶段 1：Provider 与健康探测

- 新增 `tdx_online.py` 和对应单元测试；
- 启动时对优选服务器执行真实协议探测，不以 TCP connect 代替数据探测；
- 至少保留 2 个可用服务器，建议 3–5 个；
- 使用 `get_security_bars(KLINE_TYPE_1MIN)`；
- 市场映射为深圳 `0`、上海 `1`、北京 `2`；
- 支持单股探针、100股市场探针、干跑和影子模式。

### 阶段 2：抓取、重试与检查点

- 初始使用 2 个长连接，每服务器最多 1 个工作连接；
- 请求失败后切换服务器，不在同一失效节点密集重试；
- 通常单次请求最近 800 根；积压多日时按 800 根分页回溯；
- 以 SQLite 检查点持久化已成功原始响应，任务重启后只抓取缺失股票；
- 成功发布后删除对应检查点，影子模式保留检查点和报告。

### 阶段 3：质量门禁与原子发布

- 每股每日必须为 09:31–11:30、13:01–15:00 的 240 根；
- 检查重复分钟、空 OHLC/量额、OHLC 关系和负数；
- 最终日线收盘价强对账；
- 成交量和成交额使用现有 TDX 容差与科创板已知口径规则；
- 覆盖率门槛保持 99.5%；
- 临时 Parquet、写盘校验、CRC 和 manifest 更新继续使用原子操作；
- manifest 来源标记为 `tdx-online:tcp`，记录 run ID 和服务器数量。

### 阶段 4：影子运行

- 每日 16:00 执行 TDX TCP 影子任务；
- 不改写正式分钟湖；
- 生成独立 run ID、错误统计、服务器统计、覆盖率、日线对账和耗时报告；
- 连续 3 个交易日达标后允许切换 Provider 顺序（已完成）。

### 阶段 5：生产切换与回滚

- 通过 `MINUTE_TDX_TCP_ENABLED=true` 固定 `tdx-tcp` 为主源；
- 切换后的降级顺序为 TDX TCP → 新浪 → 本地 `.lc1`；
- 单次覆盖率不足、北交所大面积缺失、对账异常或耗时过长时，仅对当次任务降级，不自动修改主源配置；
- 回滚只改变 Provider 顺序，不回退已验证发布的 Parquet。

## 5. 服务器与数据分歧策略

公开行情服务器不承诺 SLA，且实测发现不同节点在极少数分钟上存在行情修订差异。采用以下策略：

- 任务启动时对沪深北代表股进行多服务器一致性抽样；
- 普通股票使用单服务器获取，仅对对账失败或字段异常股票请求第二服务器；
- 两源不一致时以最终日线收盘、量额和 OHLC 约束裁决；
- 仍无法裁决时将该股列入缺失，不降低门禁。

## 6. 验收标准

正式切换前必须同时满足：

- 连续 3 个交易日无人工干预；
- 每日全市场覆盖率不低于 99.5%；
- 沪深北均有完整样本；
- 有成交股票的目标日时间轴为 240 根；
- 最终日线收盘价强对账无未解释失败；
- 全市场更新 P95 小于 10 分钟；
- 任一主服务器失效后可自动切换；
- 任务中断后可从检查点恢复；
- 不产生半成品 Parquet 或错误 manifest；
- 日志可区分连接失败、协议失败、空数据和对账失败。

## 7. 已批准决策

- 复用现有 `pytdx 1.72`，不直接引入 `pytdx3` 生产依赖；
- 先进行 3 个交易日影子运行；
- 首期只做每日增量，历史回补单独验收；
- 初始 2 个服务器长连接；
- 建议调度为 16:00 影子/主任务、16:30 在线降级、17:30 本地回补；
- 覆盖率门槛保持 99.5%；
- 异常股票二次取源，不对全市场执行双份下载。
