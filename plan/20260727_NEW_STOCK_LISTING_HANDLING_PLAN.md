## 1. 目标

建立从“发现新上市证券”到“行情、财务、评分和交易规则全部就绪”的自动化闭环，避免新股依赖人工导入，同时防止历史数据不足、财报不足和上市初期特殊交易规则导致错误评分。

本计划仅定义工作清单、实施顺序与验收标准，不在本阶段直接修改生产逻辑。

## 2. 当前基线

截至 2026-07-27，系统已有以下基础能力：

- `instruments` 保存 `list_date`、`delist_date` 和证券状态。
- 日线首次同步可以从上市日期开始拉取。
- 分钟数据和数据质量检查会按上市、退市日期限制有效区间。
- 活跃股票会进入财务数据更新范围。
- 选股评分少于 65 根有效日 K 时返回“数据不足”。

当前尚未形成完整闭环：

- 每日增量任务只更新证券主表中已经存在的活跃股票，不会先发现全市场新增证券。
- 腾讯数据源只能按单只证券查询，不能用于枚举全市场证券名单。
- 备用模拟数据源为静态名单，不能承担真实的新股发现职责。
- 当前数据库有 5,486 只活跃股票，`list_date` 均非空，但最新上市日期停留在 2026-04-10，最近 90 天没有新增上市记录。
- 评分、涨停识别和回测尚未覆盖上市初期的特殊交易规则。
- 系统没有“待上市、上市初期、评分预热期、正常交易”等明确生命周期状态。

## 3. 实施原则

- 不使用东方财富作为证券主表的关键依赖。
- 证券主表更新与行情增量更新解耦，前者失败不得破坏已有证券。
- 所有新增和回补任务必须幂等、可重试、可审计。
- 新股数据不足不能使用中性分掩盖，也不能生成误导性的正式评级。
- 交易规则按市场、板块和生效日期版本化，评分与回测复用同一套规则。
- 新股个股强弱判断仍必须与大盘及所属板块进行比较。

## 4. P0：证券主表自动发现

- [ ] 确定全市场证券名单的主数据源和备用数据源。
- [ ] 优先评估 Tushare `stock_basic`，并评估交易所公开数据作为备用源。
- [ ] 验证数据源对沪市、深市、创业板、科创板和北交所的覆盖。
- [ ] 新增独立的“证券主表更新”定时任务。
- [ ] 每个交易日盘前或盘后刷新全市场证券名单。
- [ ] 自动识别待上市、已上市、暂停上市和退市状态。
- [ ] 以市场、证券类型和证券代码建立稳定唯一键。
- [ ] 使用 upsert 保证重复执行不会产生重复证券。
- [ ] 保存数据源、首次发现时间、最后同步时间和同步状态。
- [ ] 证券源返回空列表或异常缩量时终止状态变更，禁止批量误标退市。
- [ ] 为新增、变更、退市和异常记录生成差异日志。
- [ ] 后台增加证券主表任务状态、更新时间、失败原因和手动执行入口。

### P0 验收门槛

- [ ] 新股出现在主数据源后一个更新周期内写入 `instruments`。
- [ ] 连续重复执行不会产生重复记录。
- [ ] 数据源故障不会删除或误退市已有证券。
- [ ] 数据库最新上市日期能够与主数据源对账。

## 5. P0：新股数据自动补全

- [ ] 发现新证券后生成数据初始化任务。
- [ ] 从实际上市日期开始回补日 K，禁止请求上市前行情。
- [ ] 将已上市新股加入分钟数据更新名单。
- [ ] 将新股加入财务数据更新清单。
- [ ] 将新股加入研究快照和本地评分数据更新清单。
- [ ] 分别记录日线、分钟、财务、研究快照和评分数据的完成状态。
- [ ] 补数任务支持断点续传、失败重试和幂等执行。
- [ ] 新股补数使用独立并发和限流，避免阻塞全市场盘后更新。
- [ ] 数据源暂时缺失时保留待补状态，不将证券标记为无效。
- [ ] 后台提供“近期上市但尚未补全”清单。

### P0 验收门槛

- [ ] 新股不需要人工搜索或导入即可进入行情列表。
- [ ] 新股能够自动进入日线、分钟、财务和研究快照更新队列。
- [ ] 任一子任务失败后可以独立重试。
- [ ] 服务重启后不会丢失待处理任务或重复写入数据。

## 6. P0：新股生命周期

- [ ] 定义 `pending_listing`：已发现但尚未到上市日期。
- [ ] 定义 `early_listing`：处于上市初期特殊交易规则阶段。
- [ ] 定义 `score_warmup`：已经正常交易但评分历史仍不足。
- [ ] 定义 `normal`：交易规则和数据覆盖满足正常处理条件。
- [ ] 生命周期根据 `list_date` 和有效交易日数量计算。
- [ ] 交易日数量使用交易日历，不使用简单自然日差值。
- [ ] 保存或计算有效日 K 数量、有效财报期数和数据覆盖率。
- [ ] 个股详情页展示上市日期、上市第 N 个交易日和当前生命周期。
- [ ] 区分“新股历史不足”“数据采集失败”和“证券停牌”。

### P0 验收门槛

- [ ] 同一新股在不同阶段能够得到确定且可解释的状态。
- [ ] 节假日和停牌不会错误推进生命周期。
- [ ] 前端、评分、回测和后台使用一致的生命周期定义。

## 7. P0：上市初期特殊交易规则

- [ ] 查阅沪深交易所、北交所现行官方规则。
- [ ] 按市场、板块、上市日期和规则生效日期建立版本化规则表。
- [ ] 处理上市初期无常规涨跌幅限制的阶段。
- [ ] 处理上市首日或特殊阶段的临时价格限制。
- [ ] 处理主板、创业板、科创板和北交所的差异。
- [ ] 涨停识别、跌停识别和连板统计统一调用规则引擎。
- [ ] 短线打板评分调用同一规则引擎。
- [ ] 回测撮合和可交易性判断复用同一规则引擎。
- [ ] 保留历史规则版本，避免使用当前规则回看全部历史。

### P0 验收门槛

- [ ] 上市初期大幅上涨不会被误判为普通涨停或连板。
- [ ] 规则变更前后的历史数据能够匹配各自生效规则。
- [ ] 评分和回测对同一交易日给出一致的涨跌停判断。

## 8. P1：评分体系的新股保护

- [ ] 少于 65 根有效日 K 时显示“新股预热”，不再只显示笼统的“数据不足”。
- [ ] 数据覆盖不足时禁止生成正式投资评级。
- [ ] 缺失指标不得默认使用中性分抬高综合分。
- [ ] 如采用可用指标重分配权重，必须同时设置覆盖率门槛和最高得分上限。
- [ ] 价值投资评分设置最低财报期数。
- [ ] 成长评分要求营收、净利润和经营现金流具备可比期间。
- [ ] 趋势评分设置最低价格和成交量历史长度。
- [ ] 短线打板评分根据上市阶段和交易规则决定是否启用。
- [ ] 所有风格均对比大盘和所属板块，输出相对强弱。
- [ ] 评分结果披露生命周期、数据覆盖率、排除指标和降权原因。
- [ ] 区分“暂不评分”“低分”和“不可交易”，避免语义混淆。

### P1 验收门槛

- [ ] 少于最低历史长度的新股不会产生正式评分。
- [ ] 缺少财报的新股不会因为中性分而获得虚高评分。
- [ ] 相同输入数据能够稳定复现评分状态和解释。
- [ ] 新股评分输出包含大盘和板块相对强弱结论。

## 9. P1：财务数据处理

- [ ] 新股上市后立即查询当前可获得的招股书和定期报告数据。
- [ ] 区分“尚未披露”“数据源暂无”“采集失败”和“解析失败”。
- [ ] 分别记录 ROE、营收、净利润、经营现金流、负债率和毛利率的覆盖状态。
- [ ] 检查招股书历史财务数据与上市后定期报告的口径一致性。
- [ ] 防止将不可比财务期间直接用于同比评分。
- [ ] 财报期数不足时降低基本面评分置信度或暂停正式评分。
- [ ] 财务采集失败自动进入重试清单。
- [ ] 新股财务数据进入现有自动更新和质量验收流程。

### P1 验收门槛

- [ ] 每个核心财务字段都能说明缺失原因。
- [ ] 不可比期间不会生成错误同比增速。
- [ ] 财务数据不足会影响评分置信度，而不是静默填充中性分。

## 13. 总体验收标准

- [ ] 新股能够自动完成发现、入库、补数、状态计算和展示。
- [ ] K 线系统不会请求或生成上市日期之前的数据。
- [ ] 特殊上市阶段不会被误判为普通涨停、跌停或连板。
- [ ] 数据不足的新股不会生成误导性正式评分。
- [ ] 新股分析始终包含与大盘及所属板块的相对强弱比较。
- [ ] 数据源异常不会破坏证券主表或已有历史数据。
- [ ] 所有任务均可审计、可重试、可恢复且幂等。
- [ ] 数据库最新上市日期、证券数量和状态能够与主数据源定期对账。
