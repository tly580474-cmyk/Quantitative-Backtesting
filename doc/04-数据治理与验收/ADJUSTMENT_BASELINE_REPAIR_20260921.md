# 复权参数覆盖缺口修复

## 原因与处理

修复前活跃股票共 5565 只，已发布复权参数 5483 只，覆盖率 98.53%。
82 只缺口股票已有日线，但没有任何复权因子。它们的存量日线均始于
2026 年 4 月之后；原日常同步只在检测到除权信号时刷新已有因子，缺少初始化路径。

腾讯接口还有两处适配缺口：无除权记录的股票在前复权请求中返回 `day`，原解析器
只读取 `qfqday`；北交所代码需要 `bj` 前缀，且旧 `fqkline/get` 仅返回最新一天，
需要使用 `newfqkline/get` 获取完整历史。保留沪深旧接口，并优先读取明确的复权字段。

## 补缺工具

在 `server` 目录执行：

```sh
npm run data:adjustments:check
npm run data:adjustments:repair
```

默认仅校验。发布前要求全部存量日线日期均有前复权参考，并检查反向日期覆盖、
最新价格锚点及所有 OHLC 的重建误差（不低于 99.5% 在一分以内）。
空数据、截断历史、重复日期、无效价格、已有未发布因子均不能自动补缺。
只有完整参考验证得到恒等变换时，才会发布因子 1。

发布使用数据库命名锁防止并行补缺；每只股票在一个事务中写入导入批次、因子和发布指针。
事务中再次检查既有因子、发布记录及原始行情；行情发生变化时拒绝写入，留待下次重试。
不改写既有发布、原始日线或复权覆盖率门槛。

每次运行在 `server/.cache/adjustment-baseline/<运行ID>/` 保存逐股原始行情、
前复权参考、推导因子、校验统计、来源指纹与批次 ID，以及汇总 `report.json`。

## 后续自动补缺

仓库提供 `scripts/systemd/quant-adjustment-baseline.service` 和同名 timer。
定时器在工作日北京时间 18:45 运行，支持漏跑补执行；成功后刷新覆盖率缓存。
失败股票保留在缺口列表并在日志中报告，下次重新校验，不会为了通过门槛写入占位因子。

```sh
systemctl status quant-adjustment-baseline.timer
journalctl -u quant-adjustment-baseline.service
```

不要批量删除随后增量刷新产生的版本。
