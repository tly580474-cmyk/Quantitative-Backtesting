# 长任务历史回答缺失修复（2026-09-24）

服务器：`192.168.2.218`。截图中三段 Pi 对话的最终回答仍在数据库中；重新进入对话时，历史接口截断了回答所在的尾部事件。

## 根因

`GET /api/agent/conversations/:conversationId/turns` 对每轮仅调用 `getEvents(run.id, -1, 300)`，但返回结果没有继续加载剩余事件。`eventsWithTerminal()` 看到任务已完成、前 300 条内又没有终止事件，就补出序号 301 的终止事件。因此页面显示“301 步”和“本轮已结束，但未生成最终回答”。报告卡片单独查询，所以仍可显示。

这不是随机的数据丢失，也不是 Pi 特有的持久化问题：只要最终回答落在第 300 条之后，就会在该历史入口被截断；短任务不受该条件影响。

## 修复与验证

- 新增完整历史读取方法：先取得当时最大序号，再以每批 1,000 条读取至该边界，避免将单页限制当作整段历史限制，也不追逐持续追加的实时事件。
- 对话分页入口、单次运行详情、旧版对话入口统一使用完整历史读取。只有读完之后，才对确实缺少终止事件的历史补充终止状态。
- 保留原有公开事件转换；旧协议的最终文本判断在完整历史上进行。原有手动事件分页接口和实时 SSE 流未修改。
- 回归覆盖第 305/315 条回答、超过 10,000 条事件、有无已保存终止事件、读取过程中新增事件及空历史。

本地后端 25 项、前端历史与实时展示相关 22 项测试通过，后端类型检查通过。服务器后端 25 项测试通过后部署并重启；健康检查正常。
