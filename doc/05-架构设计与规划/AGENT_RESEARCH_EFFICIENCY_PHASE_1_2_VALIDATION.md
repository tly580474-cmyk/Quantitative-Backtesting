## 已实现的行为

| 项目 | 实现结果 |
|---|---|
| E01 统一入口 | 按任务发现数据；返回字段、单位、实际覆盖与样例。资金流直接给出可执行命令；指数官方历史估值明确标记缺少统一入口。根目录 query 固定工作目录，结果包含行数和截断标记。 |
| E02 资金流 | 最近 N 个交易日、个股、当前行业聚合，逐日样本与日线参照数、缺失日、来源、亿元净额、正负排名。参数化 SELECT、只读事务，不触发采集。 |
| E03 参数检查 | 缺 SQL、未知参数、重复单值参数、错误位置参数、在 query 上误用日期/证券/limit 筛选均失败；预览必须显式 preview。 |
| E04 失败识别 | 在输出截断前识别退出失败、结构化失败及明确运行时错误；管道掩盖失败时保留原始退出码和判定依据，不伪造退出码。 |
| E05 普通报告 | 主代理一次生成 Markdown；聊天与 HTML 附件共用正文，服务端静态排版；不再强制调用 report-designer。单一资金流任务出现可识别的亿元日额表不一致时，由已核实数据生成替代简报，同时修正聊天与附件。 |
| E07 观测 | 终态保存按 ID 去重的工具数、失败类别、工具区间并集、阶段工具耗时、首次结构化非空数据、渲染时间、实际模型、Provider 用量及可用的 API 累计耗时。复用 terminal_json，无数据库迁移。 |

`firstValidDataMs` 表示统一入口返回可用的非空结果，不证明全市场覆盖或所有研究条件已经校验。空筛选结果可以是正确结果，此时该指标保留 null。工具阶段按命令分类；未知有效取数保持未知。`unattributedMs` 包含模型生成、请求等待和编排开销，不能解释成纯思考。没有逐请求耗时的 Provider 不补造该指标。绘图修改轮数和受控图文交付仍属于后续阶段。

## 端到端对照方法

本轮选择资金流短报告与复权选股短报告两类，改前、改后各连续重复 3 次，失败样本也保留。每轮为新会话；同一台服务器、同一实际模型 `qwen3.8-flash`、Claude 通道和相同完整提示词。旧版通过现有 API 运行，改版通过相同 AgentOrchestrator/ClaudeAgentProvider 在隔离目录运行；总耗时以运行记录 startedAt 到 finishedAt 计算。顺序为先全部旧版、再全部改版；同组轮次共享临时目录，可见前次产物。远端负载、缓存和产物复用并未完全隔离，不据此宣称总体 P95、纯粹的单因素收益或所有任务的稳定提升。Codex 通道通过协议及类型测试，未做本轮模型端到端速度对照。

验收提示明确限定已有数据、不联网补数、不改代码/配置/权威数据。数据不受新任务影响：日线使用同一已发布快照，资金流选取固定历史日期并校对样本、金额与数据指纹。每份报告检查日期、金额/收益/成交额、前五名单、样本与局限、报告附件存在性，以及是否调用 report-designer。输出篇幅另行记录，不能仅凭 status=completed 判定全部质量要求通过。

原完整计划的 14 交易日回测和 PE 定投图文报告涉及本轮未实现的配方、绘图和检查点；本轮使用较窄的复权选股作为 E01/E03/E05 验收，不把该结果外推到完整回测或图文任务。

真实 Provider 复测脚本为 `server/scripts/benchmarkAgentEfficiency.ts`，从 server 目录执行：

```text
node --import tsx scripts/benchmarkAgentEfficiency.ts cases.json output-directory 3
```

脚本仅创建自己的新运行并保存事件、报告路径和耗时；不调用 initialize() 清理其他运行。默认每轮超时 12 分钟；输出目录已有 manifest 时拒绝覆盖。

## 端到端结果

以每题 3 次的中位数比较，单位为秒：

| 任务 | 旧版三次 | 改版三次 | 中位数变化 | 耗时减少 |
|---|---|---|---|---|
| 近 5 日资金流报告 | 626.857 / 503.269 / 275.411 | 62.759 / 65.189 / 80.510 | 503.269 → 65.189 | **87.0%（约 8.7 成）** |
| 前复权 20 日选股报告 | 446.897 / 316.265 / 412.585 | 232.999 / 332.840 / 389.074 | 412.585 → 332.840 | **19.3%（约 1.9 成）** |

资金流的耗时范围从 275–627 秒降至 63–81 秒；选股从 316–447 秒降至 233–389 秒。仅这组 6 个任务的累计耗时从 2581.284 秒降至 1163.371 秒，减少 54.9%；该组合比例不代表所有研究任务的平均收益。

最终 6 轮均完成并生成报告，用户要求的核心表格经逐项人工检查，与独立查询的金额、样本、前五名单、复权收益率和成交额一致。所有运行实际模型均为 qwen3.8-flash。资金流每轮仅 1 次工具调用，13.2–14.3 秒取得有效数据；旧版调用数为 40、22、14。选股调用数由 20、15、16 变为 12、16、21，中位数仍为 16，说明公共研究配方缺失仍限制这类任务的收益。其第 2、3 轮各有一次写同名文件前未读取的工具失败，修正后完成。

旧版 6 次 report-designer 调用累计 841.035 秒（约 14 分钟）；最终 6 轮为 0 次。模型用量与阶段耗时保存于证据 JSON，Provider 自报 API 累计耗时可能高于墙钟时间，不能与工具时间直接相减。旧版失败识别有漏报，不进行“前后错误率下降百分比”的不等口径比较。

改版对照前进行过一次试跑：资金流约 44 秒，发现重复 coverage 查询与 Claude `Exit code 1` 前缀影响错误分类。随后停止了尚在运行的选股试跑，修复后开始完整六轮对照。试跑的完成/中止记录保留在服务器 `tmp_output/agent-efficiency-benchmark/pilot-before-coverage-fix`，不混入最终版本的耗时样本。

六轮对照的资金流第 3 轮暴露 UTC 时间被误读成北京时间的问题。采集代码已确认 `fetched_at` 按 UTC 写入，因此提交 `350cff4` 补充明确时区、数量差和正负天数汇总，并重跑 3 次资金流。其第 2 次虽然仅 53.158 秒，但模型把每日金额缩小 10 倍，**质量失败，不能作为合格提速样本**。该样本完整保留在 after-timezone 组，并用于服务器回放测试。

提交 `4d82f69` 加入针对日额表的金额一致性检查后，再重跑全部 3 次资金流；以上最终性能表使用 after-guard 组，不按快慢挑选样本。选股采用不受资金流修复影响的 3 次对照。共保留 20 个真实模型运行记录：6 个旧版、12 个改版/复测、2 个早期试跑（含 1 个主动中止）。

资金流指定窗口 26,036 条记录的金额、来源及最终状态指纹在验收前后相同：`03e3b3d02f7967b61deda0dbdb2b8c08c2558a2fccc813e1c1bf315d18eb45f6`。最终 17 个变更运行文件已核对，与提交代码一致。

### 质量边界与后续优先项

核心结果表应与独立查询逐项一致，但不能仅由此宣布全部研究文字通过事实校验。人工检查已发现：

- 时区修复前资金流第 1、2 轮的覆盖差值描述用了宽泛的“约 341–348 / 340–348 只”，而逐日参照数量之差实际是 343–344；第 2 轮文字称“两日流出”，表中实际有三日净流出。最终工具已经直接给出这些基础计数，避免要求模型心算。
- “查询范围含 SH/SZ/BJ”与“实际已覆盖沪深北所有股票”应区分，最终解释仍可能把查询范围写得过满；已有覆盖率说明不能代替这一语义校验。
- 改版选股第 1 轮没有报告子代理，但同一份最终正文仍先给结果表、再在报告部分重复表格。取消二次模型改写已生效，不能宣称所有重复行文都已消除。
- 不同轮次自行选择的完整窗口、退市名称过滤等边界条件可能不同，前五一致不等于所有候选集定义完全相同；正式报告应保留其实际口径。
- 最终资金流第 2 轮正文额外写了“单日极差约 657 亿元”，正确值约 684.71 亿元；核心表格正确。新增检查只覆盖可识别、明确以亿元计的日额表，在单一股票资金流窗口下生效，不覆盖全部文字衍生统计、任意格式或混合研究任务，不能宣称全文事实校验已经通过。最终 3 轮未触发替代简报；真实错误样本的触发效果由回放和编排器集成测试验证。

下一阶段建议把排名表直接从结构化结果渲染，模型只写必要解释；随后实现固定研究配方和逐项一致性校验。临时文件应使用每轮独立目录或显式复用登记：改版选股第 2 轮写同名遗留 SQL 时因“尚未读取文件”失败一次，修正后完成，未从统计中剔除。简单资金流任务可另做较短推理配置对照，但本轮没有改变模型或推理配置，也不能把剩余耗时全部归因于“思考”。
