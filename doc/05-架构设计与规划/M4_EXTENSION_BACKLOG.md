# M4 多资产研究扩展任务清单

> 建立日期：2026-08-01  
> 当前状态：**E1–E3 已完成，E4–E7 实施中；不属于已通过的 M4 v1 冻结范围**
> 基线：M4 v1 仅支持沪深 300 时点成分股、已发布 `momentum_20`、周/月调仓和
> TypeScript 权威撮合。

## 1. 扩展目标与边界

本轮扩展包含五项能力：

- 中证 500 与全 A 股时点股票池；
- 通用多因子优化器；
- 行业中性优化约束；
- 按财务公告日生效的时点化基本面；
- 多因子组合信号。

这些能力继续遵循 M4 的计算边界：DuckDB/Python 负责时点数据、横截面特征、组合分和
目标权重；TypeScript 负责协议校验、订单撮合、现金、持仓和最终权益。Python 不得直接
写最终资金账本。

“多因子组合”和“多因子优化器”必须分开：前者生成每个标的的综合分或预期收益，后者
在风险、成本、行业和持仓约束下把分数转换为目标权重。

## 3. E1：指数股票池白名单与中证 500

- [x] 将任意六位 `indexCode` 收紧为 `000300/000905` 服务端白名单；
- [x] 支持 `index:000300` 和 `index:000905`，计划中保存数据集 ID 与 checksum；
- [x] 继续使用历史发布批次的有效区间，禁止用当前成分股回填历史；
- [x] UI 增加“沪深 300 / 中证 500”选择，并展示能力边界提示；
- [x] API、队列幂等 hash 和制品清单纳入指数代码与数据集绑定；
- [x] 为两个指数建立相同日期、相同因子口径的真实快照复现证据。

验收条件：

1. 任一决策日的成员集合与对应已发布成分批次一致；
2. 修改未来成分批次不会改变过去决策；
3. `000905` 在 DuckDB 与 Python 中输出相同 universe/feature/plan hash；
4. TypeScript 拒绝目标标的落在该决策日股票池之外的计划。

完成证据（2026-08-01）：

- 中证 500 快照 `eb260586-a8d0-4c24-9171-218b1222341c-20260731103228`；
- 2026-06-01 至 2026-07-30 共 21,500 条时点输入、9 次调仓；
- DuckDB/Python 决策一致，计划 hash 为
  `ab28a921880f8f0c9efea31af97aa1d34f6cac092790b0809e87740a91843f80`；
- TypeScript 生成 119 笔订单和 39 个逐日账本点；期末权益只作为复现证据，不构成收益
  评价或承诺；
- 前后端类型检查、生产构建和 10 项定向测试通过；浏览器确认中证 500 创建入口可用。

## 4. E2：全 A 股时点股票池

- [x] 将指数型参数演进为版本化 `universeSpec`，兼容读取既有 `indexCode` 计划；
- [x] 增加 `all_a` 股票池类型，不用伪造指数代码；
- [x] 按决策日实际存在的时点行情、首个有效交易日和交易板块构造有效成员；
- [x] 首个冻结配置显式保存 SH/SZ/BJ，覆盖沪深主板、创业板、科创板和北交所；
- [x] ST/退市风险名称排除只读取决策日快照名称，不读取当前名称回填历史；
- [x] 增加上市历史、最小成交额、停牌天数和近 20 日数据完整度过滤；
- [x] 每个决策日保存过滤前数量、各原因剔除数量、逐证券原因及最终股票池 hash；
- [x] 大截面查询固定 2 GB/4 线程、90 秒、100 万输入行、两年区间及 64 MB 制品上限。

建议首个冻结默认值：上市满 120 个交易日、排除当日 ST/退市风险名称、排除最近 20 日
有效行情不足的标的；板块范围必须由计划显式保存，不使用隐藏默认值。

验收条件：

1. 上市前、退市后和当日不满足过滤条件的证券不会进入股票池；
2. 过去截面不受当前证券状态修改影响；
3. 全 A 单次运行在资源预算内完成，超限时返回确定性错误码而非拖垮 Worker；
4. 股票池过滤审计可以解释每只证券的纳入或排除原因。

完成证据（2026-08-01）：

- 既有 `indexCode` 配置经无业务语义变更的兼容层转换为 `universeSpec.type=index`；
- 全 A 计划使用 `all_a:point_in_time` 数据集标识，显式绑定 SH/SZ/BJ 与所有过滤阈值；
- 决策日无行情的未上市、退市后或停牌证券不会进入候选集合；有行情但不合格的证券保存
  `risk_name/insufficient_history/incomplete_bars/suspended/insufficient_liquidity` 原因；
- 快照 `eb260586-a8d0-4c24-9171-218b1222341c-20260731103228` 上，2026-06-01 至
  2026-07-30 生成 45,973 条合格时点输入和 9 次调仓；DuckDB/Python 决策一致；
- 计划 hash 为 `a49307fd9117371cf456ef640a0c2a87e7399d856d917c58aa7096c4b8622591`，
  TypeScript 撮合生成 125 笔订单与 39 个账本点；收益数值仅用于复现，不作为策略评价；
- 服务端类型检查、前端生产构建、定向测试与全 A 真实快照冒烟通过。

## 5. E3：多因子协议与组合分

- [x] 将单值 `featurePlan/featureValue` 演进为版本化 `factorPlan/factorEvidence`；
- [x] 每个因子保存版本 ID、方向、缺失值策略、缩尾、标准化和权重；
- [x] 首批只接受因子库中已发布且可由白名单编译器计算的因子；
- [x] 支持 `equal`、`manual`、训练期 `ic` 和 `rankIc` 权重；
- [x] 综合分默认使用逐日横截面百分位或 z-score，禁止直接相加不同量纲原值；
- [x] 缺失值策略只允许 `exclude` 或预先批准的截面填充，并进入 hash；
- [x] 保存每个标的的因子向量、综合分和完整 evidence hash；
- [x] M4 v1 单因子输入通过兼容适配器生成等价的新版协议结果。

验收条件：

1. 至少以 `momentum_20 + reversal_5` 建立多因子黄金样例；
2. 因子顺序变化但语义相同时 canonical hash 保持稳定；
3. 与因子研究 `CompositeFactorRun` 的截面值、方向和权重口径一致；
4. 任一因子版本、预处理或权重变化都会改变计划 hash；
5. 训练期权重不能读取验证期或锁定测试数据。

完成证据（2026-08-01）：

- 新增 `MultiAssetPlan/RebalancePlan 1.1` 多因子协议，旧版 `1.0` 单因子计划继续只读兼容；
- 首批白名单开放已发布 `momentum_20` 与 `reversal_5`，快照编译器拒绝未发布因子；
- DuckDB/TypeScript 计划生成器与隔离 Python Worker 均实现逐决策日缺失处理、百分位缩尾、
  横截面百分位或 z-score 标准化、方向调整和组合分；
- 每个候选标的固化原始因子向量、标准化向量、组合分和 evidence hash，计划 hash 覆盖因子
  版本、预处理、权重与训练/验证边界；
- `equal/manual/training_ic/training_rank_ic` 均使用冻结权重进入执行协议；训练权重模式强制
  `trainedThrough < validationStartsAt`，权重估计本身仍由因子研究流程完成，不在执行期重估；
- `momentum_20 + reversal_5` 黄金样例在 TypeScript 与 Python 中输出完全相同的调仓决策；
  因子顺序不影响 canonical hash，版本、权重或预处理变化会改变 hash；
- 多因子与 `CompositeFactorRun` 定向测试、服务端类型检查、前端生产构建通过；浏览器确认
  单因子兼容模式、多因子模式、标准化方法和手工权重配置可用。

## 6. E4：财务公告日时点化基本面

- [ ] 将财务报告版本作为研究快照数据集发布并纳入 checksum；
- [ ] as-of join 必须满足 `announcement_date <= decision_date`；
- [ ] 同一报告期多次公告或更正时，选择决策日前最新公告版本；
- [ ] 保存报告期、公告日、数据来源和字段级缺失状态；
- [ ] 基本面因子声明最大陈旧期，超过期限的数据按缺失处理；
- [ ] 首批建议支持 ROE、营收同比、净利润同比、资产负债率、经营现金流质量和估值字段；
- [ ] 禁止仅按 `report_period` 连接，也禁止用期末日期代替公告日；
- [ ] 报告制品展示基本面数据可用日，而不只展示报告期。

验收条件：

1. 人工构造“报告期已结束但尚未公告”的样例不得提前产生信号；
2. 修改未来公告值不影响公告日前的历史信号；
3. 更正公告只从其新公告日起生效；
4. DuckDB 查询必须显式包含公告日条件并有动态未来数据测试。

## 7. E5：通用多因子优化器

- [ ] 定义独立、版本化的 `OptimizerSpec` 和 `OptimizerResult`；
- [ ] 输入只接受综合分/预期收益、协方差或风险代理、上期持仓、成本模型和约束；
- [ ] 首批目标函数为“预期收益 - 风险惩罚 - 换手惩罚”；
- [ ] 支持总仓位、最低现金、单标的上下限、最大换手和持仓数量约束；
- [ ] 固定求解器、版本、容差、最大迭代和确定性随机种子；
- [ ] 求解失败时返回明确 infeasible/timeout/numerical 错误，不静默回退；
- [ ] TS 对输出重新校验所有硬约束，再交给权威撮合；
- [ ] 等权/评分权重继续作为基准优化器，用于一致性和回退对照，不作为隐藏回退路径。

验收条件：

1. 相同输入跨进程重复运行得到相同目标权重和 hash；
2. 约束不可行时不生成伪成功计划；
3. TS 独立校验能拒绝篡改后的权重；
4. 成本和换手惩罚增加时，固定样例换手不应反向上升；
5. 优化结果必须与等权基准并列报告，不能只展示优化后收益。

## 8. E6：行业中性优化器

- [ ] 使用决策日有效的 SW2021 行业归属，禁止当前行业回填历史；
- [ ] 保存行业分类版本、行业 exposure 和 benchmark exposure hash；
- [ ] 支持相对基准行业偏离上限，以及可选的行业绝对上下限；
- [ ] 未知行业默认不可进入正式中性优化，除非计划显式允许独立 UNKNOWN 桶；
- [ ] 行业约束与单股上限、现金、换手约束共同求解；
- [ ] TS 在收到目标权重后独立复算行业暴露并校验容差；
- [ ] 报告展示优化前后行业偏离、约束占用和不可行原因。

建议首个黄金样例使用相对股票池基准的一级行业权重，单行业主动偏离绝对值不超过 2%。
该阈值是测试起点，不应在未评审前作为所有正式策略的产品默认值。

验收条件：

1. 每个行业的主动偏离均在计划容差内；
2. 行业归属的未来修改不影响过去决策；
3. 无可行解时输出明确冲突约束集合；
4. 报告同时给出行业中性前后的收益、风险、换手和集中度，不只展示收益改善。

## 10. Schema 演进原则

1. 保留 `MultiAssetPlan 1.0` 和 `RebalancePlan 1.0` 的只读解析与历史制品下载；
2. 新能力使用新协议版本，不给 v1 字段偷偷增加不同语义；
3. canonical hash 覆盖股票池、因子版本、预处理、优化器、行业分类与基本面数据版本；
4. Python 输出完整 evidence，TS 独立校验 universe、feature、industry、constraint 和 plan hash；
5. 任一向后兼容转换都必须有固定输入/输出黄金样例。

- [ ] 行业暴露与主动偏离可逐期复核；
- [ ] 现有 M4 v1 历史计划、运行和制品回归通过；
