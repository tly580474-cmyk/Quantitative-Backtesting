## 1. 背景与测试结论

本次测试覆盖了静态代码检查、现有自动化测试、构建检查、运行中 API 数据审计，以及本地真实界面的历史对话加载和折叠交互。

### 1.1 已通过项目

- 前端测试：818/818 通过。
- 前端生产构建：通过。
- 服务端 TypeScript 类型检查：通过。
- 服务端独立测试：380/381 通过；唯一失败为因子研究测试超时，与智能体无直接关系。
- 历史对话接口可用，现有 14 次运行中有 4 次续接记录。
- 同一界面加载历史、继续对话、将中间步骤折叠为“已处理 xx 分 xx 秒”的基本链路已经可用。

### 1.2 已确认的主要问题

1. 展开“已处理”会展示原始内部推理、本机路径和环境访问计划，不符合最小信息披露原则。
2. 流式解析器一行只返回一个事件，同一消息中的后续文本或工具块会丢失。
3. Claude Code 实际输出中的嵌套 `tool_result` 未被解析；现有历史存在大量 `tool_use`，但没有 `tool_result`。
4. `error_max_turns` 等错误变体可能被解析成普通文本。
5. 实时 SSE 终止事件将退出码固定为 0；取消、失败和进程关闭可能互相覆盖状态。
6. SSE 在“补发历史”和“注册实时监听”之间存在丢事件窗口。
7. 切换历史对话时，前一个对话的展开状态会继承到新对话。
8. 失败原因通常被收进折叠区，正文只显示“失败”。
9. 历史接口一次加载完整祖先链和全部事件；现有单对话响应已约为 94KB～621KB。
10. Agent API 监听在 `0.0.0.0`，没有 Agent 专用身份验证；执行器使用 `--dangerously-skip-permissions`。
11. Agent 被提示直接读取 `server/.env`，同时事件又会持久化和展示，存在凭据暴露风险。
12. 智能体生成的 HTML 可在同源新窗口运行脚本；iframe 同时授予 `allow-scripts` 和 `allow-same-origin`。
13. 续接提示词强制“不要重新查询数据，直接生成报告”，不适合普通多轮对话。
14. 服务关闭未统一回收 Agent 子进程，服务重启也没有自动处理孤立的 `running` 记录。
15. 智能体模块没有专项自动化测试。

## 2. 修复目标

### 2.1 必须达到

- 用户能在同一对话中稳定连续追问，不因“续接”被强制转入报告生成。
- 正文只展示用户消息和最终回答；中间步骤默认折叠为安全、简洁的执行摘要。
- 不保存、不下发、不展示原始内部推理。
- 工具调用、工具结果、最终文本和错误事件完整、有序、可恢复。
- `completed`、`failed`、`canceled` 三种终态准确且不可相互覆盖。
- 断线重连不丢事件、不重复事件。
- 历史对话随消息量增长仍可分页加载，不一次性传输全部详情。
- Agent 执行、数据库访问和 HTML 报告均处于明确的安全边界内。
- 关键链路具备单元、集成和 UI 自动化测试。

### 2.2 本轮不包含

- 不更换 Claude Code 为其他模型或供应商。
- 不重做量化研究、因子或回测业务逻辑。
- 不重新设计整个平台导航和非智能体页面。
- 不在本轮引入多人协作、报告分享或公网部署。
- 不修改已有研究报告的内容结论。

## 3. 需要审核确认的架构决策

以下决策建议在开始编码前一次性确认。

### 决策 A：中间步骤展示口径

**推荐方案：只展示结构化执行摘要，不展示原始思考。**

前端允许展示：

- 正在检查数据覆盖；
- 正在运行回测；
- 已读取 590 个样本；
- 某工具执行成功或失败；
- 耗时、步骤数和经过脱敏的结果摘要。

禁止展示或持久化：

- 模型内部推理全文；
- 系统提示词；
- `.env` 内容、授权码、口令、请求头；
- 未经清洗的绝对路径；
- 任意长度的原始命令输出。

### 决策 B：对话和报告的关系

**推荐方案：普通对话与生成报告分离。**

- 普通消息默认是对话续接，可继续查询、分析和运行工具。
- “生成报告”作为显式动作或明确意图，不再要求每轮都输出 HTML。
- 报告生成完成后仍可在原对话继续追问。
- 数据是否允许重新查询由用户任务决定，不由续接状态强制决定。

### 决策 C：Agent 执行权限

**推荐方案：最小权限执行。**

- 服务默认仅监听回环地址；如需局域网访问，启用认证和来源限制。
- Agent 使用独立工作目录、只读数据库账号和允许的命令集合。
- 不向 Agent 暴露 `server/.env`；改由受控的数据访问层提供必要能力。
- 仅在明确的隔离执行环境中允许免确认模式。

### 决策 D：HTML 报告能力

**推荐方案：主站只展示受限报告，完整交互报告使用隔离源。**

- 主站卡片展示标题、摘要、静态图表或经过清洗的 HTML。
- 需要脚本交互的完整报告从独立 origin 提供。
- iframe 不同时授予 `allow-scripts` 和 `allow-same-origin`。
- 报告响应设置严格 CSP，禁止外部网络请求和访问主站 API。
- 下载 HTML 前显示“本地独立文件”安全提示。

### 决策 E：历史原始事件处理

**推荐方案：保留数据库备份，但默认读取时隐藏旧 `thought` 原文。**

- 上线新版本后，旧历史只展示用户消息、最终文本和清洗后的步骤标签。
- 原始历史不立即物理删除，先备份并验证迁移。
- 后续是否永久清理旧推理事件另行审核。

## 4. 目标事件模型

建议将当前面向模型输出的事件，改成面向产品的安全事件协议。

```typescript
type AgentEventType =
  | 'progress'
  | 'tool_started'
  | 'tool_finished'
  | 'assistant_text'
  | 'assistant_final'
  | 'error'
  | 'terminal';

interface AgentEventEnvelope {
  runId: string;
  seq: number;
  type: AgentEventType;
  timestamp: string;
  publicContent: string;
  toolName?: string;
  durationMs?: number;
  terminal?: {
    status: 'completed' | 'failed' | 'canceled';
    exitCode: number | null;
    errorCode?: string;
  };
}
```

约束：

- 一个 stream-json 输入行可以解析为 0～N 个产品事件。
- `seq` 在单个 run 内严格递增且唯一。
- `publicContent` 必须经过长度限制和脱敏。
- 原始输入仅允许进入短生命周期诊断日志，不进入前端 API；生产环境默认不记录。
- `terminal` 是唯一结束信号，必须携带真实状态和退出码。
- 工具调用使用稳定的 `toolUseId` 配对开始与结果。

## 5. 目标状态机

```text
pending ──▶ starting ──▶ running ──▶ completed
    │           │           ├──────▶ failed
    │           │           └──────▶ canceled
    │           └──────────────────▶ failed
    └──────────────────────────────▶ canceled
```

规则：

1. `completed`、`failed`、`canceled` 为不可变终态。
2. 取消操作先以原子状态更新取得所有权，再终止进程树。
3. 子进程 `close` 回调不得覆盖已有终态。
4. 超时统一进入 `failed/TIMEOUT`，不能先写 `canceled` 再写 `failed`。
5. 启动失败也必须生成并持久化 `terminal` 事件。
6. 服务启动时扫描孤立的 `starting/running` 记录，标记为 `failed/SERVER_RESTARTED` 或执行受控恢复。

- 脱敏器命中次数，不记录命中原文。

## 7. 数据迁移与兼容策略

1. 先执行数据库和报告目录备份，并验证可恢复性。
2. 新增字段和索引采用向后兼容 migration，不立即删除旧字段。
3. 读取旧事件时通过兼容适配层转换；旧 `thought` 默认不返回原文。
4. 新 SSE 协议使用版本号，例如 `agent-events-v2`。
5. 前后端在短期内支持 v1 历史读取，但新 run 只写 v2。
6. 验证新数据完整后，再评估旧原始推理数据的清理策略。
7. 旧 HTML 报告先转为隔离打开，不批量改写内容。

## 8. 发布顺序与回滚

### 8.1 推荐发布顺序

1. 脱敏器、解析器和状态机测试先落地，不对用户开放。
2. 数据库兼容 migration。
3. 服务端 v2 事件写入与 SSE 重放。
4. 前端 v2 渲染、折叠和分页。
5. 对话/报告模式拆分。
6. 报告隔离服务与安全策略。
7. 小范围运行真实任务，观察状态、事件缺口和历史响应。
8. 全量启用并移除旧写入路径。

### 8.2 回滚原则

- migration 必须可向后兼容，回滚应用时不要求立即回滚数据结构。
- v2 写入保留功能开关；发生异常可暂停新 Agent 任务而不影响历史读取。
- 报告隔离异常时退化为“仅下载”，不能退回同源任意脚本执行。
- 状态机异常时禁止自动重试和重复启动，优先保护进程与数据一致性。
