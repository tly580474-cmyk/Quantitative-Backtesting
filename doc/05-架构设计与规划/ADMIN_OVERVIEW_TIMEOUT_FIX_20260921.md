# 管理台总览超时修复（2026-09-21）

已部署至 `192.168.2.218:/opt/quant-backtest`，北京时间 15:50 线上复验通过。

## 原因与证据

浏览器显示“无法连接后端服务”，但后台、MySQL、Nginx 正常，健康轮询持续返回 200。
Nginx 记录 15:31:59、15:32:21 的两次 `/api/admin/overview` 请求为 499：
客户端在新增的 20 秒超时到达时中止请求。前端此前将超时统一归类为网络故障，提示后端未运行。

总览在覆盖矩阵的 15 分钟缓存过期时同步调用 `buildDataCoverageMatrix`，扫描大表；
原有覆盖缓存到 15:32:26 才更新。首次总览失败后，健康轮询只更新已有总览，无法从空状态恢复。
这是管理台超时与恢复逻辑的缺陷，与技能拆分无关。

## 修复行为

- 覆盖扫描在后台运行；冷缓存立即返回其他诊断，旧缓存可展示但明确标注“尚未刷新”。
- 同一运行时、数据库池和数据根目录共用一个扫描任务，避免并发请求重复扫描；失败后至少等待一分钟重试。
- 扫描结果完成后自动更新页面；首次总览失败也自动重试，隐藏页面暂停、失败退避。
- 区分请求超时、取消和网络故障，不再让超时提示用户检查 3001 端口。
- 更新总览时保留其他模块的错误信息，不重新启动全部可选探测。
