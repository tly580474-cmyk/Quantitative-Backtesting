# 下一阶段开发计划：MVP 3 + MVP 4 收尾

> 建立日期：2026-08-02
> 状态：已批准，待开始实施
> 基线：M0–M5 已全部完成；MVP 1（Strategy IR + DSL）与 MVP 2（VectorBT 实验 Worker）已完成，
> MVP 3（高级 Python 实验室）与 MVP 4（研究 Agent 闭环）各缺 2 项能力。

## 1. 背景与现状

| MVP | 状态 | 缺失项 |
| --- | --- | --- |
| MVP 1：Strategy IR + DSL | 已完成 | — |
| MVP 2：VectorBT 实验 Worker | 已完成 | — |
| MVP 3：高级 Python 实验室 | 部分完成 | Backtrader 事件策略、自定义机器学习模型 |
| MVP 4：研究 Agent 闭环 | 部分完成 | 假设生成 Agent、代码修复 Agent |

设计约束（来自 `EXPERIMENT_AGENT_STRATEGY_RESEARCH_DESIGN.md`）：

- ADR-04：多资产策略必须由组合引擎统一撮合，禁止单标的回测结果拼接；
- ADR-05：向量化/事件引擎只做筛选，候选必须经权威引擎复算才能进入门禁；
- ADR-11：首期不自动修复编译或运行时策略错误，改为确定性错误分类 + 智能解释 +
  用户重新提交（因此"代码修复 Agent"按此口径实施，不实现黑盒改码）。

## 2. 阶段目标

补齐高级 Python 实验室（MVP 3）和研究 Agent 闭环（MVP 4）的 4 项缺失能力，并完成
全链路集成验收，使 MVP 3 / MVP 4 达到与 MVP 1 / MVP 2 相同的完成标准。

## 3. 工作包

### N1：Backtrader 事件策略适配（MVP 3）— 前置风险项

**先行一致性论证**：引入 Backtrader 前必须完成相同输入、相同信号、相同费用下的
黄金样例一致性测试（设计文档 7.3 节硬要求）。若暴露不可修复的口径差异，回退为
"自研最小事件引擎"。

| 步骤 | 内容 | 验收条件 |
| --- | --- | --- |
| 1.1 | 黄金样例一致性测试（先行） | Backtrader 与现有 TS 引擎的订单/权益差异在容差内 |
| 1.2 | 事件驱动订单生命周期适配层 | 覆盖 next_open 成交、整手、佣金/印花税/滑点、停牌、涨跌停，与 TS 撮合口径逐项对齐 |
| 1.3 | 白名单策略包装器 | Backtrader 策略以 B 档插件形式注册，参数经 Schema 校验 |
| 1.4 | 双引擎复算流程 | 事件引擎结果必须经权威 TS 引擎复算后才能进入门禁（ADR-05） |

### N2：自定义机器学习模型支持（MVP 3）

| 步骤 | 内容 | 验收条件 |
| --- | --- | --- |
| 2.1 | 时点化训练数据导出 | 模型训练仅使用决策日已知数据，禁止未来数据泄漏 |
| 2.2 | 模型协议与版本化 | MLModelSpec 固定特征清单、预处理、训练/验证切分、种子；模型产物含 SHA-256 和依赖锁定 |
| 2.3 | 白名单框架接入 | 首批支持 sklearn 系模型，禁止任意模型代码直接执行（走 M5 沙箱 C 档） |
| 2.4 | 模型→因子桥接 | 模型输出转为标准因子向量进入现有 multi-factor 协议（复用 E3），不做独立资金账本 |
| 2.5 | 稳健性校验 | 训练窗口扰动、种子扰动、特征扰动测试纳入现有门禁体系 |

### N3：假设生成 Agent（MVP 4）

| 步骤 | 内容 | 验收条件 |
| --- | --- | --- |
| 3.1 | 假设模板与能力边界 | 从现有因子库、指标注册表和已发布版本自动生成假设候选（能力清单驱动） |
| 3.2 | 假设→实验规格管线 | 假设生成后自动映射为 StrategyExperimentSpec 草稿，不直接运行 |
| 3.3 | 批量假设筛选队列 | 复用 M2 幂等运行 + M5 向量初筛，批量评估假设候选 |
| 3.4 | 假设管理 UI | 假设列表、状态（draft/evaluated/rejected）、与实验版本的关联追踪 |

### N4：智能报错映射与用户重提流程（MVP 4 — 替代"代码修复 Agent"）

设计文档 ADR-11 已明确否决"黑盒代码修复 Agent"，改为确定性错误分类 + 智能解释 +
用户重新提交。N4 按此口径执行。

| 步骤 | 内容 | 验收条件 |
| --- | --- | --- |
| 4.1 | 错误分类全面覆盖 | SCHEMA_INVALID/SEMANTIC_CONFLICT/UNSUPPORTED_CAPABILITY/COMPILE_FAILED/DATA_MISSING 等九类错误码由组件直接产生，不靠 LLM 猜测 |
| 4.2 | 中文解释 Agent | 基于结构化错误 + 能力清单生成可点选修正建议，只解释不改策略 JSON |
| 4.3 | 修正建议→重提闭环 | 用户按建议修改描述后重新提交，版本未运行时更新草稿、已运行则创建新版本 |
| 4.4 | 防御性测试 | 提示词注入、越权修改字段、VALIDATION_FAILED 降级为可重试错误等对抗场景 |

### N5：MVP 3 + MVP 4 集成验收（收尾）

| 内容 | 说明 |
| --- | --- |
| 端到端全链路冒烟 | 自然语言 → 假设 Agent → 实验规格 →（单标的/MultiAsset/ML/事件引擎）→ 门禁 → 报告 |
| 黄金样例矩阵扩充 | 增加 Backtrader、ML 模型、假设驱动实验的固定样例 |
| 对抗与安全测试 | 按设计文档 17.3 节补齐沙箱、伪造清单、并发锁竞争场景 |
| 能力清单自动发布 | 新能力只有通过验收才向 Agent 和 UI 发布（沿用 E7 模式） |
| 验收文档 | 参照 M0–M4 验收报告格式输出 MVP 3/4 收尾验收记录 |

## 4. 优先级与依赖

```
N1（事件引擎一致性论证）→ N2（ML 模型）→ N3（假设 Agent）→ N5 集成
N4（错误映射）可并行，不依赖 N1–N3
```

- **N1 是前置风险项**，应先投入，其结果决定引入 Backtrader 还是自研最小事件引擎；
- **N2 依赖 M5 沙箱**（已就绪）与 E3 多因子协议（已完成）；
- **N4 与 N3 均复用现有实验规格/门禁基础设施**，可并行开发。

## 5. 完成定义

- [ ] Backtrader（或自研事件引擎）与权威 TS 引擎黄金样例一致性通过；
- [ ] 机器学习模型只使用时点化数据，产物可复现、可追溯；
- [ ] 假设生成不直接运行，全部经实验规格与人工确认；
- [ ] 错误分类全部由组件产生，Agent 只解释不修改策略；
- [ ] MVP 3 / MVP 4 全链路集成验收通过，能力清单自动发布。
