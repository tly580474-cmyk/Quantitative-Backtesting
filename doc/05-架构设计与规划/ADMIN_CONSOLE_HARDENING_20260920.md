# 管理台技术债治理（2026-09-20）

本轮采用分层改造，保留现有 React 管理台、Fastify API、配置定义和诊断服务。问题主要出在数据刷新、状态生命周期和资源控制，替换框架并不能直接解决这些问题。

## 问题与落地行为

| 编号 | 改造行为 |
| --- | --- |
| 1 | 保存配置成功后重新读取配置列表；列表刷新失败时明确提示“已保存，但列表刷新失败”。 |
| 2 | 普通文本、路径、数字和模型字段回填已有值；密钥输入保持为空，不回填掩码。 |
| 3 | 更新 API 从 `ADMIN_CONFIG_DEFINITIONS.restartRequired` 计算重启提示，取消按名称前缀维护的第二套规则。 |
| 4 | 总览、配置、重启能力、公网访问和 Agent 数据分别提交加载结果；失败提示带模块名，保留已有结果。总览失败也能进入配置页和使用已获取的重启能力。 |
| 5 | 管理 API 使用实时 MySQL 探测，缓存 5 秒、合并并发探测、3 秒超时。探测失败释放连接；超时后才获得的连接也会释放。 |
| 6 | 备份状态每次读取磁盘上的 `latest.json`，完成状态核验文件名、普通文件类型、大小和可用的修改时间；状态文件采用临时文件加 rename 发布。 |
| 7 | Agent API 和页面增加 Claude CLI 版本、工作目录配置和 Git Bash 配置卡片。版本探测结果缓存 60 秒。 |
| 8 | 数据更新轮询：有任务时 10 秒、空闲时 60 秒；备份运行时 3 秒、空闲时 60 秒。隐藏页面暂停，重新可见时刷新。顺序调度避免请求重叠，失败指数退避至最多 5 分钟。后端进度采集也有缓存和并发合并，大清单与日线最新日期单独缓存 60 秒。 |
| 9 | 失败任务用 SQL `COUNT + NOT EXISTS` 判定同 `run_key` 的更晚成功记录，使用已有复合索引；不再读取历史 JSON 快照。查询失败显示任务诊断不可用。 |
| 10 | 所有管理鉴权共享按 socket IP 的失败次数窗口：60 秒内第 10 次失败开始返回 429 和 `Retry-After`。正常已认证轮询不累加失败次数，地址表有上限。 |
| 11 | 浏览器先用 Bearer 申请 60 秒有效、限定备份 ID、只能消费一次的下载凭证，再用原生表单 POST 下载。管理令牌不进入 URL，前端不再创建大型 Blob。 |
| 12 | 每次成功导出后清理专用目录中的旧完成 SQL 备份。默认最多 3 份、保留 7 天，始终保留本次成功文件；跳过临时文件、其他文件和符号链接。清理失败通过状态警告展示。 |
| 13 | 前后端均阻止将包含当前管理令牌的字符串写入业务密钥，包括前后空格、Bearer 前缀和其他前后缀。 |

## 配置与运行范围

`server/.env.example` 新增：

```dotenv
ADMIN_BACKUP_RETAIN_COUNT=3
ADMIN_BACKUP_RETAIN_DAYS=7
```

保留策略在下次成功导出时执行，配置随后端启动读取；本轮开发没有操作实际备份目录。备份目录为 `BACKUP_ROOT/admin-database-exports`。外部导出程序若要作为管理台的最新备份，应以原子方式更新该目录的 `latest.json`，遵守现有文件命名和元数据协议。

实时数据库恢复本轮覆盖管理 API。业务路由、调度器和 Agent 的启动注册仍沿用应用已有生命周期：若它们因启动时数据库不可用而未启用，仍需恢复数据库后重启后端。界面中的 Provider 实际运行状态继续反映这一点。

限流状态和下载凭证保存在单个后端进程内。当前使用直接 socket IP，不信任客户端的 `X-Forwarded-For`；反向代理后的客户端会共享代理地址的额度。若部署改为多实例，应在入口统一限流，并让一次性下载凭证的签发与消费使用共享存储或固定路由。

## 验证

- 管理台生产构建与服务端 TypeScript 检查。
- UI 回归：局部接口失败、总览失败后进入配置、普通字段回填、保存后刷新、密钥不回填、Claude 卡片。
- 轮询回归：空闲/运行频率、隐藏与恢复、慢请求不重叠、失败退避。
- 服务端回归：数据库离线/恢复/掉线、连接超时释放、鉴权限流和伪造转发头、配置元数据、业务密钥防误填。
- 备份回归：磁盘文件删除、外部元数据替换、并发导出互斥、中断后重试、数量与天数保留规则、一次性下载与过期。
- SQL 语义在隔离内存数据库中验证：较晚成功、等时成功、过早成功、空 run key、超出时间窗口、归档和删除任务。此测试在支持 `node:sqlite` 的 Node 版本执行。

后续已完成部署：临时 MySQL 库真实导出与恢复、1 GiB 浏览器下载、生产 MySQL `EXPLAIN` 和线上接口验收均通过。生产全库尚未进行恢复演练；具体范围与限制见 [部署验收记录](ADMIN_CONSOLE_DEPLOYMENT_20260920.md)。
