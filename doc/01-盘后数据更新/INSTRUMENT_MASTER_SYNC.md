# 证券主表与新股接入

## 1. 目标

证券主表更新负责在日线、分钟、财务和研究快照任务之前发现新上市证券，并维护待上市、
正常交易和退市状态。该链路不使用东方财富。

## 2. 数据源顺序

1. 配置 `TUSHARE_TOKEN` 时，使用 Tushare `stock_basic` 获取上市、待上市和退市名单。
2. 未配置 Token 或 Tushare 请求失败时，使用新浪财经全市场 A 股名单。
3. 新浪名单不提供上市日期时，仅对数据库中尚不存在的证券查询新浪公司资料页。
4. 腾讯仍负责主要日线和实时行情；不支持的新 `920xxx` 北交所代码由新浪日 K 降级。

同步不会根据免 Token 新浪名单直接批量退市证券。退市状态只接受明确提供退市日期的
主数据源，避免接口缩量、分页失败或临时缺失导致误退市。

## 3. 调度

```dotenv
MARKET_DATA_ENABLED=true
INSTRUMENT_SYNC_ENABLED=true
INSTRUMENT_SYNC_TIME=15:20
MARKET_DATA_SYNC_TIME=15:30
TUSHARE_TOKEN=
```

- 证券主表默认在交易日 15:20 更新。
- 个股日线默认在 15:30 更新。
- 未配置 `TUSHARE_TOKEN` 时自动使用新浪免 Token 备用源。
- 后端在配置时间之后启动时会补偿执行当天尚未成功的证券主表任务。
- 证券主表、指数数据集、财务和日线任务使用各自类型的互斥锁，不再相互阻塞。

后台“数据更新进度”会展示证券主表的来源、处理数量、失败数量和完成时间。

## 4. 写入保护

- 市场、证券代码和证券类型组成唯一键。
- 写入按每批 500 条执行幂等 upsert。
- 备用源缺少上市日期或行业时保留数据库已有值。
- 数据源返回空名单时终止任务。
- 当前主表不少于 1,000 条时，返回数量低于当前数量的 70% 会终止任务。
- 失败同步不会删除或批量修改已有证券状态。
- 新股资料补充失败不会阻止证券进入主表，下一次同步会继续尝试补充。

## 5. 新股下游处理

新证券写入 `instruments` 后：

- `status=active` 且到达上市日期的证券进入日线增量任务。
- 日线历史从 `list_date` 开始，不请求上市前日期。
- 分钟湖根据证券主表、上市区间和最终日线确定目标证券。
- 财务任务会把没有财报覆盖的新活跃证券列为优先目标。
- 研究快照和覆盖率矩阵按当前活跃证券重新计算。
- 少于 65 个有效交易日时，前端评分显示“新股预热”，不生成正式评分。

## 6. 上市初期交易规则

评分侧使用版本化规则解析器：

- 沪深注册制新股上市后前 5 个交易日不按普通涨跌停识别。
- 北交所新股上市首个交易日不按普通涨跌停识别，此后使用 30% 涨跌幅。
- 创业板、科创板正常阶段使用 20%，沪深主板正常阶段使用 10%。
- 沪深主板风险警示股票正常阶段使用 5%。

生命周期按有效交易日计算，不使用自然日。少于评分最低历史长度时状态为
`score_warmup`，上市初期特殊交易阶段为 `early_listing`。

历史主板注册制之前的上市首日规则不会在缺少显式历史规则记录时进行猜测。

## 7. 手动执行

```http
POST /api/sync/instruments
Content-Type: application/json

{"providerId":"sina-instruments"}
```

配置 Tushare 后可以改为：

```json
{"providerId":"tushare-instruments"}
```

查询进度：

```http
GET /api/sync/jobs/{jobId}
```

## 9. 后续复核

- 本地存在但新浪当前交易列表缺少的 3 只股票不得自动退市，应使用明确的退市数据源复核。
- Tushare Token 配置后，应再次对比上市、待上市和退市三类名单。
- 今日首发证券应在收盘日线任务后检查行情、估值和分钟数据覆盖。
- 财务任务完成后检查新增证券的财报覆盖及“尚未披露/采集失败”缺失原因。
